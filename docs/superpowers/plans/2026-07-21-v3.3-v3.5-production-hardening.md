# V3.3-V3.5 Production Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use $superpower-executing-plans to implement this plan task-by-task in the current workspace. Subagents are intentionally not used in this run because the active project instruction says not to spawn agents unless explicitly requested.

**Goal:** Ship V3.3, V3.4, and V3.5 together as one bounded production-hardening version without Docker-dependent gates.

**Architecture:** V3.3 exposes the existing in-process `BrokerRuntimeMetrics` snapshot through a protocol/admin API and CLI command. V3.4 strengthens resilience through deterministic unit/embedded-channel fault-injection tests around availability, throttling, metrics, and controller readiness. V3.5 extends the existing fetch benchmark with a broker network transport selector while keeping the benchmark local and resource-light.

**Tech Stack:** Java 17, Maven, JUnit 5, Netty embedded channels, existing MiniMQ protocol records/serdes, existing demo CLI and fetch benchmark.

---

## Scope and Constraints

- Do not run Docker/Testcontainers gates in this version because the Docker API is currently unavailable.
- Prefer focused Maven tests with `-Djacoco.skip=true`; avoid repeated full `mvn clean verify`.
- Keep runtime commands local and bounded; do not run anything that can restart the machine.
- If a blocker survives five bounded attempts, record it in the test report or known-issues doc instead of continuing to loop.
- Preserve unrelated dirty work from V3.0.1-V3.2; only edit files required for V3.3-V3.5 and docs/version sync.
- Do not commit unless the user explicitly requests it after validation.
