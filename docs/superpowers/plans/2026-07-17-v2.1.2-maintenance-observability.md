# V2.1.2 Maintenance Observability Implementation Plan / V2.1.2 维护可观测性实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> **面向智能代理：** 必须使用子技能：采用 superpowers:subagent-driven-development（推荐）或 superpowers:executing-plans，逐项实施本计划。步骤使用复选框（`- [ ]`）语法跟踪。

**Goal / 目标：** Finish accurate dry-run reports, maintenance metrics, reader-aware skipping, compaction budgets, maintenance windows, and Java manual entrypoints for V2.1.2.

完成 V2.1.2 的准确 dry-run 报告、维护指标、reader 感知跳过、压缩预算、维护窗口和 Java 手动入口。

**Architecture / 架构：** Keep `LogManager` as the serialized coordinator and `SegmentedPartitionLog` as the partition mutation boundary. Preview and execution share retention-then-compaction planning semantics; execution uses non-blocking reader quiescence and reports immutable action/status snapshots through `PartitionManager`.

保持 `LogManager` 作为串行协调器，`SegmentedPartitionLog` 作为分区修改边界。预览和执行共用先保留、后压缩的规划语义；执行时采用非阻塞 reader 静默机制，并通过 `PartitionManager` 报告不可变的动作/状态快照。

**Tech Stack / 技术栈：** Java 17、Maven reactor、JUnit 5，以及现有分段存储/目录/WAL 代码。

## Global Constraints / 全局约束

- Preserve V2.1.1 on-disk formats, WAL replay, and checkpoint compatibility.
  保持 V2.1.1 磁盘格式、WAL 重放和检查点兼容性。
- Do not add a broker protocol, HTTP endpoint, CLI command, background executor, or persistent metric store.
  不增加 broker 协议、HTTP 端点、CLI 命令、后台 executor 或持久化指标存储。
- Dry-run must not mutate log/index files, catalogs, checkpoints, or records.
  dry-run 不得修改日志/索引文件、目录、检查点或记录。
- Real maintenance must apply retention before compaction.
  真实维护必须先应用保留，再应用压缩。
- Reader conflicts must return without waiting or mutating.
  发生 reader 冲突时必须立即返回，不得等待或修改数据。
- Append-triggered runs obey the UTC window; manual runs bypass only the window.
  append 触发的运行遵守 UTC 窗口；手动运行只绕过窗口限制。
- Full Maven verification must pass the existing 90 percent JaCoCo line gate.
  完整 Maven 验证必须通过现有 90% JaCoCo 行覆盖率门槛。

### Task 2: Implement Reader Skip And Metric Semantics / 实现 Reader 跳过与指标语义

**Files / 文件：**
- Modify: `mq-storage/src/main/java/com/minimq/storage/MaintenanceStatus.java`
- Modify: `mq-storage/src/main/java/com/minimq/storage/SegmentedPartitionLog.java`
- Modify: `mq-storage/src/main/java/com/minimq/storage/LogManager.java`
- Test: `mq-storage/src/test/java/com/minimq/storage/SegmentedPartitionLogSnapshotTest.java`
- Test: `mq-storage/src/test/java/com/minimq/storage/LogManagerMaintenanceTest.java`

**Interfaces / 接口：**
- Produces: `MaintenanceStatus.SKIPPED_READERS`.
  输出：`MaintenanceStatus.SKIPPED_READERS`。
- Produces: one non-blocking maintenance attempt that either owns reader quiescence or returns a skip report.
  输出：一次非阻塞维护尝试；要么取得 reader 静默状态，要么返回跳过报告。

- [ ] **Step 1: Add failing reader-skip and last-status tests / 添加失败的 reader 跳过和末次状态测试**

Hold a real internal read snapshot with reflection, invoke maintenance on a
separate future with a one-second timeout, and assert `SKIPPED_READERS`, positive
`skippedDueToReaders`, unchanged records, and no blocked future. Add a second
test proving dry-run increments `dryRuns` without changing `lastRunStatus`.

使用反射持有真实内部读快照，在独立 future 中调用维护并设置一秒超时，断言返回 `SKIPPED_READERS`、`skippedDueToReaders` 为正、记录不变且 future 未阻塞。再增加一个测试，证明 dry-run 会增加 `dryRuns`，但不会更改 `lastRunStatus`。

- [ ] **Step 2: Run both tests red / 运行两个测试并确认失败**

Run: `mvn -pl mq-storage -am -Dtest=SegmentedPartitionLogSnapshotTest,LogManagerMaintenanceTest test -gs .mvn/settings.xml -s .mvn/settings.xml`

Expected: FAIL because maintenance currently waits and dry-run overwrites the last status.

预期：FAIL，因为当前维护会等待，并且 dry-run 会覆盖上一次状态。

- [ ] **Step 3: Replace waiting acquisition with try-acquisition / 用尝试获取替代等待获取**

Under `readerMonitor`, return false when `activeReaders > 0`; otherwise set
`maintenanceDeleting = true`. Check this before compaction planning reads,
catalog publication, or cleaned-file writes. On a conflict, return no executed
actions and increment `skippedDueToReaders` by one skipped maintenance attempt.

在 `readerMonitor` 下，如果 `activeReaders > 0` 则返回 false；否则设置 `maintenanceDeleting = true`。必须在压缩规划读取、目录发布或写入 cleaned 文件之前进行此检查。发生冲突时，不返回任何已执行动作，并按一次被跳过的维护尝试增加 `skippedDueToReaders`。

- [ ] **Step 4: Aggregate status with explicit precedence / 按明确优先级汇总状态**

Preserve `SKIPPED_READERS` when no actions execute. Count enabled real attempts
in `runs`; update actual bytes/segments only from executed actions; do not let
`recordDryRun` update `lastRunStatus`. Increment one failure for a propagated
real-pass exception.

没有动作执行时保留 `SKIPPED_READERS`。`runs` 统计已启用的真实尝试；实际字节数/segment 数只根据已执行动作更新；`recordDryRun` 不得更新 `lastRunStatus`。真实运行异常向上传播时，失败计数增加一次。

- [ ] **Step 5: Run storage tests green / 运行 storage 测试并确认通过**

Run: `mvn -pl mq-storage -am test -gs .mvn/settings.xml -s .mvn/settings.xml`

Expected: all common and storage tests pass.

预期：所有 common 和 storage 测试通过。
