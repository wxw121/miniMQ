# V2.3.2 Replica Fetch Connection Pooling Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use $superpower-executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking via update_plan.

**Goal:** Remove per-partition/per-loop TCP and `NioEventLoopGroup` churn from replica fetch by reusing connections per leader broker.

**Architecture:** Add a small `ReplicaConnectionPool` owned by `ReplicaFetcher`. The pool keeps one `LeaderReplicaClient` per `(host, port)` leader key, reuses a shared Netty worker group, invalidates failed or NOT_LEADER clients, and closes all pooled resources when the fetcher stops.

**Tech Stack:** Java 17, Netty, Maven, JUnit 5, MiniMQ broker replication package.
