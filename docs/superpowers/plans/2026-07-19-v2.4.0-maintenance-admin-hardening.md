# MiniMQ V2.4.0 Maintenance Admin Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use $superpower-subagents (recommended) or $superpower-executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking via update_plan.

**Goal:** Harden the existing V2.4.0 maintenance APIs with shared-token authorization, broker-scoped asynchronous execution, an explicit CLI target, and enabled retention/compaction integration coverage.

**Architecture:** `BrokerServer` owns one `MaintenanceAdminService` backed by a named single-thread `ThreadPoolExecutor` with queue capacity one. The service authenticates requests, rejects overlapping destructive runs, and returns asynchronous results that `MqRequestHandler` writes on the originating Channel EventLoop.

**Tech Stack:** Java 17, Netty 4, Maven reactor, JUnit 5, existing MiniMQ protocol and storage APIs.

```java
static String[] parseSingleHostPort(String broker) {
    if (broker.contains(",")) {
        throw new IllegalArgumentException("--broker must contain exactly one host:port");
    }
    String[] hp = broker.split(":", 2);
    if (hp.length != 2 || hp[0].isBlank() || hp[1].isBlank()) {
        throw new IllegalArgumentException("--broker must be host:port");
    }
    int port = Integer.parseInt(hp[1]);
    if (port < 1 || port > 65_535) {
        throw new IllegalArgumentException("--broker port must be between 1 and 65535");
    }
    return new String[] {hp[0], Integer.toString(port)};
}
```
