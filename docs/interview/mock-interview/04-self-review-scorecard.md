# 模拟面试复盘量表

每轮结束后，给每项 1–5 分并记一条证据。低于 3 分的项，下轮只挑 1–2 个重点改进，避免泛泛刷题。

| 维度 | 1 分表现 | 3 分表现 | 5 分表现 | 本轮分数/证据 |
| --- | --- | --- | --- | --- |
| 结论先行 | 绕圈、没有结论 | 基本能先答结论 | 结论、适用条件和取舍清楚 | |
| 技术准确 | 混淆语义或夸大保证 | 主线正确，有少量遗漏 | 能区分 at-least-once、最终一致、锁边界等 | |
| 项目实证 | 泛泛而谈或虚构 | 能关联一个模块 | 能说明真实模块、测试/验证与未做边界 | |
| 结构表达 | 点状罗列 | 有原理和方案 | 原理 → 落地 → 指标/失败处理 → 取舍完整 | |
| 追问应对 | 被追问后矛盾 | 能补充细节 | 能收窄边界、说明如何验证，不编造 | |
| 业务意识 | 只讲组件 | 能提到用户影响 | 会定义正确性、降级语义、成本和风险 | |
| 时间控制 | 明显超时/太短 | 大部分在时限内 | 30 秒、90 秒、3 分钟版本切换自然 | |

## 轮次复盘模板

```text
日期：
岗位侧重：Java / 中间件 / 分布式 / 系统设计
本轮最稳的 2 题：
本轮卡住的 2 题：
出现的夸大或不确定表述：
下轮只练的 2 个动作：
需要回到哪份资料：
```

## 常见修正清单

- 把“保证不丢”改为“在哪个边界做到什么语义，失败如何处理”。
- 把“加缓存/加机器”改为“先看什么指标，保护什么依赖，再做哪种改造”。
- 把“我做过”改为“项目中已实现 X；生产业务我会按 Y 落地”。
- 把“重试”补全为“幂等前提、错误分类、次数、退避抖动和死信/补偿”。
- 把“分布式锁解决”补全为“唯一 token、安全释放、租约边界及数据库幂等兜底”。
