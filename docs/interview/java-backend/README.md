# MiniMQ：Java 后端面试资料包

**目标岗位：** 3 年以上 Java 后端社招。  
**使用原则：** 讲清自己真实做过的部分；技术结论必须可追溯；未完成的验证主动说明边界。

## 怎么使用

| 面试场景 | 先看 | 目标 |
| --- | --- | --- |
| HR / 一面项目介绍（90 秒） | [项目卡](01-project-card.md) → [讲述稿](02-resume-and-pitch.md) | 说清项目定位、核心链路和一个亮点。 |
| 技术一面（3 分钟） | 项目卡 → 讲述稿 → [Java 问答](04-java-backend-qa.md) | 用两个技术挑战建立可信度。 |
| 技术二面 / 现场演示（5 分钟） | [演示手册](03-demo-runbook.md) → 问答 | 演示真实主流程，并能解释故障转移与取舍。 |
| 简历投递前 | 讲述稿 → [证据与性能](05-evidence-and-performance.md) | 选择符合本人贡献的简历版本，不夸大指标。 |

## 资料包内容

1. [一页项目卡](01-project-card.md)：背景、架构、难点、证据和边界。
2. [简历与讲述稿](02-resume-and-pitch.md)：保守/标准/强化版本，以及 90 秒、3 分钟、5 分钟话术。
3. [现场演示与录屏手册](03-demo-runbook.md)：Web 主流程、三 Broker failover、降级方案。
4. [Java 后端深挖问答](04-java-backend-qa.md)：并发、网络、存储、可靠性、消费语义和工程质量。
5. [证据与性能](05-evidence-and-performance.md)：可引用数字、复测模板和已知限制。

## 统一事实边界

| 标记 | 含义 | 面试表达 |
| --- | --- | --- |
| **已实现** | 当前源码与文档记录的能力。 | “项目实现了……，代码路径是……” |
| **历史证据** | 有日期与版本的既有报告。 | “在 2026-08-14、`cdaa377` 的全量验证中……” |
| **待复测** | 当前提交没有新的可引用结果。 | “我保留了复测命令，面试前会在当前环境复跑，不把历史结果当成当前结论。” |
| **非目标 / 限制** | 有意未做或环境未完成的范围。 | “这是教学型实现；事务、EOS、unclean election 不在范围内。” |

当前 V5.0.0 资料来自根 [README](../../../README.md)、[架构文档](../../architecture.md)、[系统设计](../../design.md)、[测试文档](../../testing.md)。

## 必须如实说明的限制

- Docker-gated 的 real-etcd Failsafe 集成验证尚未执行；详见 [已知问题](../../known-issues-2026-07-20-v3.0.1-v3.2.md)。
- 事务、exactly-once semantics（EOS）与 unclean election 是明确非目标，不应描述为已支持。
- 历史性能数据与运行机器、JDK、参数相关，当前版本若未复测必须标为“待复测”。
- 仓库无法证明的个人职责必须替换为自己的真实贡献，不能照抄成“独立负责”或“主导”。
